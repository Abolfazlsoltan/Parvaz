# Parvaz — Android air-combat campaign

Parvaz is a mobile-first arcade aircraft game built with **Godot 4.4.1**. The native Godot project is in `godot/`.

## Current game features

- Portrait-first Android interface, built with Godot Control nodes rather than manual touch hit-testing.
- Persian is the default language; English can be selected in Settings. The selection is saved.
- Large, scrollable menus and settings, with all sound controls inside Settings.
- Touch input is routed to gameplay only after native UI controls have consumed their events.
- The Android export is configured without camera, microphone, location, storage, network or vibration permissions. The CI build inspects the final APK manifest and fails if any of these unnecessary permissions appears. Gameplay and progress are local.

- An eight-mission campaign with sequential unlocks and persistent progress.
- Four additional mission slots shown as locked, ready for future updates.
- Eight playable aircraft with different handling, armor and weapon patterns.
- Temporary combat rewards, including smart homing targeting and an autonomous wingman escort.
- Touch-first steering, a dedicated circular dash control, double-tap dash and second-finger dash.
- Flight School help, difficulty settings, audio controls, achievements and saved progress.
- A short aircraft take-off animation after each mission is cleared.

## Build and download the Android APK

1. Open the repository's **Actions** tab.
2. Select **Build Parvaz Android APK**.
3. Open the latest successful run.
4. Download the `Parvaz-Android-APK` artifact.

The workflow validates Godot editor import, starts the main scene headlessly, checks for GDScript and resource errors, exports the Android APK, verifies the APK archive and signature, and only then uploads it.

## Mobile controls

- Drag anywhere on the battlefield to steer. Weapons fire automatically.
- Tap the circular **DASH** control, double-tap, or use a second finger to dash.
- Use the pause control to pause, restart the current mission or return to the menu.
- Collect dropped power cores to activate temporary abilities.

## Android test build

The workflow creates a debug-signed APK for installation and testing. Because the debug key is generated by CI, a new build may not update an already installed copy. Uninstall the previous test APK before installing a build signed with a different debug key.

## Signing security

A previous release-signing key was committed to the public repository history. It must be treated as compromised and must not be used for a production store release. The current workflow no longer reads or uses that key, and no release passwords are stored in the repository.

For a future production release, generate a new keystore privately and store the keystore and its credentials as GitHub Actions secrets. Never commit the keystore, its Base64 form, passwords, or private signing material.
